# 多币种处理（个人财务助理）

skill 对多币种采取「**原币记录 + 基准币种换算**」的双轨策略，覆盖个人常见场景
（工资本币 + 海淘/留学/外币资产）。

---

## 1. 币种识别
- 交易 `currency` 字段用 ISO 4217 代码：CNY / USD / EUR / JPY / GBP / HKD。
- 从文本/截图识别时按符号与关键词判断：
  - `$` / 美元 / 美金 / USD → USD
  - `€` / 欧元 / EUR → EUR
  - `£` / 英镑 / GBP → GBP
  - 港币 / HKD / HK$ → HKD
  - 日元 / 円 / JPY → JPY
  - `¥` / `￥` / 元 / 人民币 / CNY → CNY（**注意**：`¥` 同时是 CNY 与 JPY 符号，
    当上下文为中文消费且无「日元」字样时默认 CNY）
- 未识别时默认 CNY，并在录入回显中提示，避免静默错算。

## 2. 换算机制
- 维护 `rates.json`：`{ "base": "CNY", "rates": { "CNY": 1.0, "USD": 7.1, ... } }`。
- `amount_base = amount（带符号）× rates[currency]`（base=CNY 时即乘以该汇率）。
- **换算冻结**：录入时按当时汇率写入 `fx_rate` 并锁定 `amount_base`，保证历史趋势一致；
  后续改汇率只影响新交易，不回溯历史（符合个人记账「按发生时的价」的直觉）。
- 命令：
  - 查看：`finance_engine.py rate list`
  - 设置：`finance_engine.py rate set USD 7.2`（设置 1 USD = 7.2 基准币）
  - 改基准币：`finance_engine.py rate set EUR 1 --base EUR`

## 3. 报表中的币种视角
- **基准币种视角**：所有汇总（收入/支出/储蓄率/预算）统一换算到 base，便于总量判断。
- **原币视角**：报告单列「币种维度（原币）」，列出各币种原币净流量，不换算，
  用于核对外币账户对账单、避免混合误读。
- **账户维度**：账户名本身可带币种语义（如「美元信用卡」），与 currency 字段交叉验证。

## 4. 多账户
- `account` 为自由文本，支持任意数量账户：储蓄卡、信用卡、支付宝、微信、现金、外币账户等。
- 报告「账户维度」按账户汇总净流量，快速看出资金在哪些账户进出。
- 同一笔跨账户转账：记为两笔（A 账户支出 −、B 账户收入 +），`merchant` 标注「转账」，
  避免重复计入消费。

## 5. 边界与免责
- 汇率为用户手动维护的近似值，非实时行情；大额跨币决策前提醒用户核实实时汇率。
- 本 skill 不接入银行 API，所有数据来自用户提供的账单/截图/手动录入。
